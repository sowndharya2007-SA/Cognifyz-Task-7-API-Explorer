Understanding OAuth 2.0 & API Security

1. What is OAuth 2.0?

OAuth 2.0 is the industry-standard protocol for delegated authorization. It allows a third-party application (the Client) to access protected user resources on an HTTP service (the Resource Server) on behalf of a user (the Resource Owner), without exposing the user's password.

2. The Four Core Roles

Resource Owner The end-user who grants access to their protected data or account.
Client The application requesting access (e.g. mobile app or web client).
Authorization Server Authenticates the owner and issues signed access tokens (e.g., Auth0, Google Identity).
Resource Server The API hosting the protected data that validates the bearer access tokens.

3. Authorization Flows (Grant Types)

Authorization Code + PKCE

Recommended for SPAs and mobile apps. Obtains an authorization code via a secure browser redirect, then exchanges it alongside a cryptographic code verifier for an Access Token.

Client Credentials Flow

Used for server-to-server communication where no individual user is involved. The backend presents its own Client ID and Secret to obtain a service-level token.

Refresh Token Flow

Allows clients to obtain new short-lived access tokens without forcing the user to re-authenticate when tokens expire.

4. When is OAuth Required vs. Not Required?

Requires OAuth 2.0

  • Accessing private user data (e.g. reading private bookshelves, user profile)
  • Performing state mutations (e.g. adding reviews, borrowing an ebook)
  • Granular permission scoping (read vs write)

Does Not Require OAuth (This Project)

  • Public, read-only catalog searches (e.g., Open Library Search API)
  • Open data endpoints requiring zero personal identification
  • Protected on the backend via Flask-Limiter rate limits and caching instead
